# AskHub のリニューアル

AskHub（アプリ・オーケストレーター・ループの仕組み）を作り直すための設計の文書。
2026-11-03 の壁打ちで決めたことを正本としてまとめる。実装の Issue と PR は、この文書に沿って進める。
決めたことを変えるときは、先にこの文書を直す PR を出す。

## 目的

**AskHub だけで、ループ開発のすべてを進められるようにする。**

約 1 か月の運用で、次のことが分かった。

- 人の作業の大半が AskHub の外にある。ループの起動の準備、CI の失敗の調査、表示のずれの片付けなど、エラーや詰まりのたびに人が GitHub を開いて原因を探し、Claude に頼んで直している
- 不具合のたびに機能を継ぎ足してきたので、同じ規則が Swift・シェル・プロンプトの何か所にも別々に書かれ、状態の置き場所も GitHub・各 Mac のファイル・プロセスのメモリに割れている
- 人の確認の仕組み（仮決めの一覧・実機確認の Issue）が、実際にはほとんど見られていない。質問への回答も、分からないまま答えるしかない作りになっている

リニューアルでは、エラーの検知・表示・復旧の操作を AskHub の中に収めることを優先する。

## 前提

- アプリもオーケストレーターも入れ直してよい。今の仕組みからの移行と後方互換は考えない
- 今のリポジトリ（ask-hub-apple）で作り直す。作業は長く使う作業ブランチ `renewal` で行い、できあがったら develop に取り込んで切り替える
- 最初の版は Apple（iOS・macOS のクライアントと、Apple のアプリのリポジトリ）だけを作る。Android は後から足す

## 用語

| 用語 | 意味 |
| --- | --- |
| クライアント | 人が操作する AskHub のアプリ（iOS・macOS は SwiftUI。Android は後から Jetpack Compose） |
| 対象のリポジトリ | AskHub でループ開発を回すリポジトリ。登録するだけで、どの Mac にも置かない |
| 状態リポジトリ | 機械の状態（ゴール・進み具合・ジョブと試行・Mac の印）を置く private のリポジトリ |
| 共通リポジトリ | CI・リリースのワークフローと道具を全リポジトリに配る public のリポジトリ（仮に app-kit） |
| 司令塔 | 常時オンの Mac で動き、ジョブを作って配る常駐のプログラム |
| ワーカー | 各 Mac で動き、割り当てられたジョブを実行するプログラム。Claude をタスクごとに呼ぶ |
| ジョブ・試行 | 仕事の単位と、その 1 回の実行。すべての仕事をこの 1 つの型で扱う |
| 人の意図 | 回答・説明を求める・おまかせ・開始・指示など、機械を動かす人の書き込み。AskHub が署名して書く |
| 人が決めていない判断 | 「おまかせ」にした質問と、ユーザーから見える挙動・仕様・見た目に関わる仮決め。最終 PR で確認する |
| 人がする作業 | App Store Connect の Web でしかできない設定など、AskHub だけではできない作業 |
